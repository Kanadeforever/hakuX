# hakuX 简体中文自动构建说明

## 上游检查与发布

工作流每天 UTC 03:17 查询 `rfandango/hakuX` 的 Latest Release。发现当前仓库尚未发布的版本后，检出对应源码、应用汉化、修补应用内升级检查地址、构建并签名 APK。Release 只附带 APK、`SHA256SUMS.txt` 和 `translation-audit.txt`。

汉化版使用上游应用包名追加 `.zhcn`，与官方版并行安装。APK 使用仓库 Secrets 中已有的固定社区签名。不要更换签名密钥或将密钥提交到公开仓库。

## 应用内升级检查

应用内更新检查必须读取当前汉化仓库（Actions 运行时的 `GITHUB_REPOSITORY`），而不是官方上游仓库。工作流在获取上游源码后运行 `tools/localization/patch_update_repository.py`：

- 只扫描 Android 应用源码与资源中的文本文件；
- 优先替换 GitHub Releases API 地址及 Release 下载地址；
- 兼容在更新器中单独配置仓库 owner 或 `owner/repo` 的实现；
- 不无差别修改普通项目主页链接；
- 若检测到升级代码仍指向 `rfandango/hakuX`，立即终止构建并输出具体文件，避免发布错误版本。

## 版本号与 Release 标签

汉化版 Gradle `versionName` 与 Release 标签均采用上游标签原值，例如 `v1.2.0`。APK 资产名仍包含 `-zh-CN`，Release 标题仍明确标记简体中文版。这样应用读取自己仓库的 Latest Release 时，当前版本标签与 APK 内版本号一致；上游发布 `v1.2.1` 后，新汉化版同样使用 `v1.2.1`。

旧格式 `zhcn-v1.2.0` 的 Release 保留，不会自动删除。首次运行新工作流时，会检查新的同版本标签是否存在；不存在则为当前上游版本重新构建并发布一个标签与 `versionName` 一致的 Release。之后再按新标签规则去重。

## 汉化与未翻译报告

- 继续使用现有 `localization/strings_zh_cn.json` 和 `localization/android_strings_zh_cn.json`。
- 资源 ID 对应的译文按稳定 ID 导入；原文变化、占位符不兼容和新增资源会记录到审查报告。
- 按已选择的方案 B，存在未翻译候选不会阻止发行；至少有一项翻译命中上游界面才允许继续发布。

## 固定签名

必须在 GitHub 仓库 Actions Secrets 中保留：

- `ANDROID_KEYSTORE_BASE64`
- `ANDROID_KEYSTORE_PASSWORD`
- `ANDROID_KEY_ALIAS`
- `ANDROID_KEY_PASSWORD`

这些值只用于构建，不得写入源码、翻译表或 Release 附件。

## 构建环境与已知限制

工作流使用 JDK 21、Android SDK 36、Build Tools 36.1.0、NDK 29.0.14206865、CMake 3.30.3 和 Ninja，并保留此前已验证的 Linux `llvm-strip`、子模块初始化、脚本换行和 Gradle Java 路径兼容处理。

升级补丁针对 Android 源码中可识别的 GitHub 仓库地址。如果上游重构了更新机制，脚本会在构建前失败并列出原因，而不是静默发布仍指向官方仓库的 APK。首次使用后应检查 Actions 日志中的“将应用内升级检查切换到汉化仓库”步骤和 Release 中的审查报告。

当前补丁已通过合成源码测试和静态检查；真实上游云端构建、APK 安装覆盖和设备端升级提示仍需实测。
